# Halyk AI Challenge — решение

AI-агент, который читает «грязные» финансовые документы и реестр транзакций и определяет,
соблюдены ли финансовые ковенанты корпоративных кредитов. Результат — `submission.json`
(12 заёмщиков × 3 ковенанта = 36 ячеек: `status`, `actual`, `evidence_txn_id`).

## Архитектура (гибрид: LLM читает, код считает)

Правила кейса требуют **собственной реализации**, а не «слить ответ из ИИ». Поэтому система
разделена на слои, где ИИ — инструмент чтения, а расчёт детерминированный и воспроизводимый:

```
documents/*.pdf ──► [extract] ──► cache/enrichment/<sc>.json ──┐
                    (LLM/ручной)   категории транзакций,        │
                                   связанные стороны, курсы,    ├─► [engine] ─► submission.json
                                   реклассификации, скаляры     │   (детерминизм)
master_ledger_2025.csv ──────────► [ledger] ───────────────────┘
                                                                    [score] ─► сверка с ground_truth
```

| Файл | Роль |
|---|---|
| `specs/covenants.json` | **Пороги и определения всех 36 ковенантов**, извлечённые из ДЕЙСТВУЮЩИХ договоров. Ядро логики. |
| `src/ledger.py` | Загрузка реестра, фильтр по сценарию, применение обогащения (FX, категории, связанные стороны). |
| `src/engine.py` | Детерминированный расчёт `actual`/`status`/`evidence` по типу ковенанта. |
| `src/build_submission.py` | Прогон по 12 сценариям → `submission.json`. |
| `score.py` | Метрика по официальной формуле кейса, сверка с `ground_truth.json`. |
| `cache/enrichment/<sc>.json` | Выход слоя чтения документов (пока — ручной; далее — LLM). |

Запуск: `python -m src.build_submission && python score.py`

## Что уже сделано и проверено

- **Извлечены все 12 действующих договоров** (устаревшие редакции 2024 г. отсеяны по маркеру
  «НЕДЕЙСТВУЮЩАЯ РЕДАКЦИЯ»). Все 36 ковенантов закодированы в `specs/covenants.json`.
- **Движок реализует все типы ковенантов**: коэффициенты, агрегатные min/max, «наибольшая
  статья», платежи связанным сторонам (абсолют и доля от выручки), springing, обязательства
  на дату.
- **Проверено на P1 6.3**: движок воспроизводит эталон точно (283664.18, COMPLIANT, полный
  балл ячейки 1.000), включая отсев ловушки (Kaspi Marine 18.7% — не связанная сторона).

## Таксономия документов (на каждого заёмщика)

1. Действующий кредитный договор — пороги ковенантов.
2. Устаревшая редакция (2024) — **игнорировать** (явный маркер в шапке).
3. KYC-досье — связанные стороны (доля ≥20% или явный список).
4. Аудиторский отчёт «АУДИТОРСКОЕ ДЕЛО № ACC-xxxx» — **курсы валют** (Примечание 9) и
   **переклассификации**.
5. Шум: отчёты «Проект Атлас», процедуры KYC, логи, переписка.

## Ловушки, которые обрабатываются

- Старые редакции договоров; суб-счета (`ACC-7802-04` и т.п.).
- Разные валюты (USD/EUR) — конвертация по курсу из аудита.
- Переклассификации аудиторов (двигают суммы между категориями и в числителе/знаменателе).
- Начисления с пустой суммой в леджере (`TXN-P7-0033` налог, `TXN-P8-0031` персонал) —
  значение берётся из аудиторского отчёта (`amount_overrides`).
- Связанные стороны на грани порога (18.7% против 20%).

## Осталось (слой extract)

Заполнить `cache/enrichment/<sc>.json` для всех 12 заёмщиков: категории транзакций,
курсы EUR, связанные стороны из KYC, переклассификации и скаляры из аудита. Это единственный
слой, где нужен разбор свободного текста — его автоматизирует LLM (Claude API), либо
заполняется вручную. Движок и метрика уже готовы принять этот вход.
